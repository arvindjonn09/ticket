# Completion API contract

All paths use `/api`, existing session/CSRF guard, UUIDs, tenant scoping and revision conflicts. Money uses integer minor units; currencies are three uppercase letters. Existing incident endpoints remain.

Incident submission additionally accepts optional `callerId` (defaults to the authenticated actor). Only agents may select another active same-tenant caller. Both ticket types store the authenticated actor as `submittedById`. Non-agents can submit only `Self Service`; agents can record `Email`, `Phone`, `Walk In`, or `Self Service`. Existing records are backfilled from their caller; a database insert trigger supplies that legacy default for direct imports, while API creation always sets the actor explicitly.

- `GET /requests/catalog` → `{items: CatalogItem[], users:[{id,name}]}`; active users for requested-for selection. CatalogItem `{id,name,categoryId,unitCostMinor,currency,recurringPeriod:null|string,requiresManager,requiresVp,vpThresholdMinor:null|number,alternateApproverId:null|string,vpApproverId:null|string,active,revision}`.
- `GET /admin/request-items` → `{items:CatalogItem[],approvers:[{id,name}]}`; `POST /admin/request-items[/:id]` body catalog fields except id; update includes revision, active; create active defaults true. manager and VP booleans configurable; VP threshold optional and currency is item's currency.
- `POST /requests` + Idempotency-Key body `{itemId,requestedForId,quantity,summary,description,justification?,subcategoryId?,channel?}` → TicketDetail. Price comes from catalog. Request prefix SR, separate counter. Channel defaults Self Service.
- `GET /approvals` → `{approvals:[{id,ticketId,number,summary,stage,status,version,approverId,approverName,correctionReason,revision,requestedForName,totalCostMinor,currency,createdAt,callerName,itemName,justification}]}`. Stage manager/vp; status Pending/Approved/Rejected/Invalidated. Queue returns currently actionable stage only. Relevant request detail from `GET /tickets/:id`; approvers receive public content only.
- `POST /approvals/:id/decision` body `{revision,version,decision:'Approved'|'Rejected',comment?}` → TicketDetail. Revision is ticket revision. Reject requires comment. No stale or duplicate decisions.
- `GET /approvals/delegations` → `{delegations:[{id,delegateId,startsAt,endsAt,revision}],users:[{id,name}]}`; `POST /approvals/delegations` body `{delegateId,startsAt,endsAt}` (ISO datetime) and `POST /approvals/delegations/:id/revoke` `{revision}`. Actor nominates direct eligible delegate, no chains.
- `GET /admin/approval-corrections` → `{tickets:[{id,number,summary,revision,correctionReason}]}`; summary is generic correction text, preserving ticket confidentiality. `POST /requests/:id/correct-approvals` body `{revision,reason}` re-evaluates after user/catalog configuration correction → `{id,revision}`; MFA admin only. Catalog approval-policy changes re-evaluate nonterminal requests. Decisions and fulfilment recheck current manager/VP authority; drift invalidates prior approvals and returns 409 after saving the new approval version.
- `POST /requests/:id/change` body `{revision,reason,itemId,requestedForId,quantity,unitCostMinor?}` → TicketDetail; assigned-group agent or MFA admin (admin cannot read unrelated ticket contents). Re-evaluates approvals, invalidates all prior decisions. Optional unit price agent correction; bounded integer.
- `POST /tickets/:id/manage` body `{revision,action:'triage'|'transfer'|'category'|'assign',reason,priority?,severity?,departmentId?,categoryId?,subcategoryId?,assignedToId?}` → TicketDetail. Own-group agents; assignment requires queue owner/substitute. Sensitive flag never clears.
- `GET /tickets/:id/assignment-options` → `{users:[{id,name}],canAssign:boolean}` for assigned-group agents; users are active agents in that group.
- Existing `POST /tickets/:id/state`: add `reason?`, `holdReason?`, `duplicateOfId?`. Holds require reason, resume previous state. Cancellation requires reason; employees only own Open/Pending Approval. SR Complete requires agent fulfilment resolution + customerSummary; approval blocks In Progress.
- `GET /tickets` adds `type=incident|request`, `departmentId`, `categoryId`, `channel`, `assignedToId`, `assigned=unassigned|me`, `untriaged=true|false`. `assignedToId` and `assigned` are mutually exclusive. Search includes permitted caller/requested-for names within the same record authorization filter. `/catalog` additionally returns `agents:[{id,name}]` limited to active agents in the viewer's current groups (empty for non-agents).
- `GET /reports/summary` → `{total,byState:[{state,count}],byDepartment:[{departmentId,departmentName,count}],limitReached}` authorization-filtered (max 200 list records).
- `GET /tickets/:id/history` → `{events:[{id,action,actorName,createdAt}]}`; public audit metadata only; group agents also receive detail.

TicketSummary adds `type`, `requestedForId:null|string`, `requestedForName:null|string`, `itemId:null|string`, `itemName:null|string`, `quantity:null|number`, `unitCostMinor:null|number`, `totalCostMinor:null|number`, `currency:null|string`, `justification:null|string`, `approvalVersion:number`, `approvalCorrectionReason:null|string`, `untriaged:boolean`, `channel:string`, `holdReason:null|string`, `previousState:null|string`. States add Pending Approval and Rejected. TicketDetail adds `approvals:[{id,stage,status,version,approverId,approverName,decidedById,decidedByName,comment,decidedAt,correctionReason}]`.

User schema additions owned by backend migration 004: managerId UUID nullable self-relation; approverEligible Boolean default false; isVp Boolean default false; revision Int default 0. Department queueOwnerId/substituteId UUID nullable User composite FK. Category allowIncidents/allowRequests Boolean default true. Root/user worker should expose/configure these using existing roles; approver is eligibility, not a fourth role.

Migration 009 adds a required same-tenant `submittedById` user relationship. TicketSummary includes `submittedById`, `submittedByName`, and `duplicateOfId:null|string`. Submitters and callers retain public access to their tickets; internal notes still require membership of the recorded support group.
